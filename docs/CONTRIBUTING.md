# راهنمای مشارکت

پیش از هر تغییر، این سند را بخوانید. هدف پروژه، محاسبه‌ای **قطعی، قابل حسابرسی و فارسی‌زبان** برای حقوق و دستمزد ایران است.

## آماده‌سازی محیط

```bash
# پیش‌نیازها: Node.js 20.11+، pnpm 10، و برای دسکتاپ: Rust stable
pnpm install

pnpm lint          # ESLint (شامل jsx-a11y)
pnpm typecheck     # TypeScript strict
pnpm test          # Vitest
pnpm build         # ساخت همه بسته‌ها + خروجی ایستای وب
```

قلاب‌های Husky به‌طور خودکار با `pnpm install` فعال می‌شوند:

- `pre-commit`: ESLint و Prettier روی فایل‌های مرحله‌شده (lint-staged).
- `pre-push`: بررسی نوع‌ها و آزمون‌های واحد.

## قواعد کد

| قاعده                          | توضیح                                                                                  |
| ------------------------------ | -------------------------------------------------------------------------------------- |
| ممنوعیت `any`                  | به‌جای آن `unknown` + باریک‌سازی نوع؛ در تنظیمات ESLint به‌صورت error اعمال شده است    |
| کامنت‌ها انگلیسی، متن‌ها فارسی | پیام‌ها، برچسب‌ها و هشدارهای کاربر به فارسی روان و رسمی                                |
| موتور محاسبه خالص              | هر تابع در `packages/core` بدون وابستگی به React، مرورگر یا Dexie؛ ورودی و خروجی آشکار |
| قطعیت عددی                     | محاسبات با ریال صحیح؛ هر گردکردن با `roundRial` و در نقطه مشخص                         |
| ردیابی                         | هر محاسبه باید `calculationTrace` با شرح فرمول و مرجع قانونی برگرداند                  |
| داده شخصی                      | هیچ متن شناسایی‌کننده‌ای به سرویس تحلیل یا لاگ بیرونی فرستاده نشود                     |
| بدون CDN                       | فونت، آیکون و کتابخانه همه از بسته‌های پروژه بارگذاری می‌شوند                          |

## ساختار کامیت

از قالب Conventional Commits با توضیح فارسی استفاده کنید:

```
feat(core): افزودن ضریب شب‌کاری ۱٫۳۵ به موتور محاسبه
fix(db): جلوگیری از حذف آخرین کاربر مدیر
docs(legal): به‌روزرسانی معافیت سال ۱۴۰۵
test(web): پوشش جریان ورود گروهی کارکنان
```

## افزودن پارامتر قانونی سال تازه

1. فایل `packages/legal/src/profiles/<year>.ts` را از سال گذشته بسازید و مقادیر ابلاغی را وارد کنید.
2. پروفایل را در `packages/legal/src/registry.ts` ثبت کنید و `verified: true` را تنها پس از تطبیق با بخشنامه رسمی بگذارید.
3. عددهای مرجع را در `packages/core/src/__tests__/payroll.test.ts` به‌روزرسانی کنید (سناریوهای S1 تا S5) و تغییر نتیجه را دستی بازبینی کنید.
4. `docs/LEGAL.md` را به‌روزرسانی کنید و منبع هر رقم را ذکر کنید.

## آزمون‌ها

| نوع            | فرمان                           | نکته                                           |
| -------------- | ------------------------------- | ---------------------------------------------- |
| واحد           | `pnpm test`                     | `packages/core` باید ≥۹۵٪ پوشش خطوط داشته باشد |
| پوشش           | `pnpm test:coverage`            | آستانه‌ها در `vitest.config.ts` هر بسته        |
| سرتاسری        | `pnpm --filter web test:e2e`    | نیازمند `pnpm exec playwright install`         |
| دسترس‌پذیری    | بخشی از آزمون سرتاسری           | `@axe-core/playwright`، صفر خطا در WCAG 2.1 AA |
| تصاویر مستندات | `pnpm --filter web screenshots` | خروجی در `docs/screenshots`                    |

هر تغییر در محاسبه، بدون آزمون عددی پذیرفته نمی‌شود.

## انتشار نسخه

1. شماره نسخه را در `package.json` ریشه، `apps/web/package.json`، `apps/desktop/package.json` و `apps/desktop/src-tauri/tauri.conf.json` هم‌راستا کنید.
2. `docs/CHANGELOG.md` را به‌روزرسانی کنید.
3. برچسب بزنید: `git tag v1.2.0 && git push origin v1.2.0`.
4. جریان `Release desktop app` بسته‌ها را می‌سازد، امضا می‌کند و `latest.json` را در همان انتشار می‌گذارد.
5. جریان `Deploy PWA to GitHub Pages` با ادغام در `main` نسخه وب را منتشر می‌کند.
